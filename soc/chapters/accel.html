이종 컴퓨팅과 가속기

한 사람이 모든 일을 잘할 수는 없다. SoC도 그렇다. 순서가 복잡한 일은 CPU가, 같은 계산을 수천 번 반복하는 그래픽은 GPU가, 행렬 곱 덩어리인 신경망은 NPU가 맡는다. 이 장은 가속기가 얼마나 빨라질 수 있는지의 한계(암달의 법칙), 그리고 GPU와 NPU가 각자의 방식으로 병렬성을 뽑아내는 원리를 실험한다.

  • 암달의 법칙으로 가속기의 전체 속도 향상을 계산하고, 오프로드 오버헤드의 영향을 안다.
  • GPU의 SIMT 실행과 분기 발산(divergence)이 활용률을 떨어뜨리는 원리를 이해한다.
  • 시스톨릭 어레이가 행렬 곱을 데이터 흐름으로 처리하는 과정을 따라간다.
  • 처리 장치별 와트당 연산(TOPS/W)을 비교한다.

01암달의 법칙

작업의 비율 \(f\)만 가속기로 \(S\)배 빠르게 할 수 있다면, 나머지 \(1-f\)는 그대로 남는다. 아무리 \(S\)를 키워도 전체 속도 향상은 \(1/(1-f)\)를 넘지 못한다. 게다가 데이터를 가속기로 넘기고 결과를 받는 데 시간 \(o\)가 든다.

$$\text{Speedup} = \frac{1}{(1-f) + f/S + o}$$

읽는 법. 가로축은 가속기 속도(로그), 곡선은 f별 전체 속도 향상이다. f = 90 %이면 가속기를 1000배 빠르게 해도 10배를 넘지 못한다. 오버헤드를 넣으면 작은 작업은 오히려 느려질 수 있다 — 그래서 NPU에는 큰 덩어리의 일을 한꺼번에 넘긴다.

02GPU: 같은 명령, 수천 개의 데이터

GPU는 32개(제품에 따라 64개) 스레드를 한 묶음(워프)으로 묶어 같은 명령을 동시에 실행한다(SIMT). 픽셀·정점처럼 모든 데이터에 같은 계산을 하는 일에는 완벽하다. 그런데 스레드마다 if 조건 결과가 다르면, 워프는 두 갈래를 차례로 실행하며 각 갈래에서 해당하지 않는 스레드를 쉬게 한다(분기 발산). 연산기의 절반이 놀 수 있다.

발산한 워프 비율
연산기 활용률

읽는 법. 워프 8개(각 32스레드)의 실행 타임라인이다. 칸 하나 = 스레드 하나 × 명령 하나, 색칸 = 실제 일한 스레드, 빈칸 = 마스크로 쉰 스레드. 데이터를 조건별로 정렬하면 워프 안의 스레드가 같은 길로 가 발산이 사라진다 — GPU 프로그래밍의 대표적인 최적화다.

03NPU: 시스톨릭 어레이

신경망 연산의 90 % 이상은 행렬 곱이다. NPU의 핵심인 시스톨릭 어레이는 곱셈–누산기(MAC) 격자에 가중치를 미리 올려 두고(weight-stationary), 입력을 왼쪽에서 오른쪽으로, 부분합을 위에서 아래로 한 칸씩 흘려 보낸다. 심장이 피를 뿜듯(systole) 매 클록 데이터가 이웃으로 넘어가며, 한 번 읽은 데이터를 여러 번 재사용해 메모리 접근을 최소화한다.

클록

읽는 법. 가운데 3×3 격자가 MAC 처리 소자(PE), 안의 금색 숫자가 미리 올린 가중치 W다. 왼쪽에서 입력 행렬 X의 원소가 비스듬히 엇갈려 들어오고(파랑), 각 PE는 들어온 입력 × 가중치를 위에서 내려온 부분합에 더해 아래로 넘긴다(초록). 아래로 빠져나온 값이 결과 Y = X·W의 원소다. 오른쪽 표에서 정답과 비교해 보자.

04와트당 연산

實驗실험 3-4사진 한 장 분류에 드는 에너지

읽는 법. 막대는 처리 장치별 전력(로그)이다. 효율 가정: CPU 0.05, GPU 1, DSP 2, NPU 10 TOPS/W (INT8 실효값, 대략). 빨간 선은 휴대 기기가 AI 작업에 쓸 수 있는 1 W 남짓의 예산. 같은 실시간 카메라 AI를 CPU로 하면 수십 W가 필요하다.
