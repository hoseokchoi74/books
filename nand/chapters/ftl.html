Chapter 09 第九章 · 譯

FTL과 가비지 컬렉션

운영체제는 저장 장치를 "번호 붙은 칸들의 배열"로 보고 아무 칸이나 덮어쓴다. 그런데 NAND는 쓴 페이지를 덮어쓸 수 없고, 지우려면 수십 MB 블록을 통째로 지워야 하며, 같은 블록을 수천 번 지우면 닳아 버린다. 이 둘 사이를 통역하는 펌웨어가 FTL(Flash Translation Layer)이다. 이 장에서는 직접 작은 SSD를 굴려 보며 쓰기 증폭이 왜 생기는지 확인한다.

  • 제자리 갱신 불가(erase-before-write) 제약과 그로 인한 "다른 곳에 쓰기(out-of-place update)"를 설명할 수 있다.
  • 논리 주소(LBA)–물리 페이지 매핑 테이블과 유효/무효 페이지 개념을 안다.
  • 가비지 컬렉션(GC)의 동작과 희생 블록 선택 정책을 실험한다.
  • 쓰기 증폭(WAF)과 오버프로비저닝(OP)의 관계를 정량적으로 이해한다.
  • 웨어 레벨링과 TRIM의 역할을 안다.

01덮어쓸 수 없는 메모리

호스트가 LBA 5번을 고쳐 쓰면, FTL은 기존 페이지를 지우지 않는다. 대신 비어 있는 다른 페이지에 새 데이터를 쓰고, 매핑 테이블의 LBA 5 항목을 새 위치로 바꾼 뒤 옛 페이지에 "무효(invalid)" 표시만 한다. 빈 페이지가 모자라면 무효 페이지가 많은 블록을 골라 아직 유효한 페이지만 다른 곳으로 옮기고(복사) 그 블록을 지운다. 이것이 가비지 컬렉션이다. 호스트는 한 번 썼지만 NAND는 옮겨 쓰기까지 여러 번 쓰게 된다.

사용법. LBA 버튼을 눌러 쓰자. 초록 = 유효, 빨간 줄무늬 = 무효, 빈칸 = 지워진 페이지. 오른쪽 표는 매핑 테이블이다. 빈 페이지가 바닥나면 GC를 눌러 보자(또는 쓰기가 자동으로 GC를 부른다). 유효 페이지가 적은 블록을 고를수록 복사가 적다.

02쓰기 증폭과 오버프로비저닝

쓰기 증폭 계수(WAF)는 NAND에 실제로 쓴 양을 호스트가 쓴 양으로 나눈 값이다. WAF가 2면 SSD는 수명을 두 배 빨리 쓰고, 쓰기 성능도 절반이 된다. WAF를 줄이는 가장 확실한 방법은 사용자에게 보이지 않는 여분 공간, 오버프로비저닝(OP)을 두는 것이다. 여분이 많을수록 GC가 블록을 고를 때 무효 페이지가 많이 쌓인 블록을 찾기 쉽다.

$$\text{WAF} = \frac{\text{NAND 쓰기}}{\text{호스트 쓰기}},\qquad \text{균일 무작위 + 탐욕 GC 근사: } \text{WAF} \approx \frac{1 + \text{OP}}{2\,\text{OP}}$$
OP = (물리 용량 − 논리 용량) / 논리 용량. 소비자용 SSD는 7 % 남짓(1 TB = 1,000 GB 대 1,024 GiB 차이 등), 데이터센터용 쓰기 집중 SSD는 28 % 이상을 둔다.

읽는 법. 왼쪽 격자가 블록 64개(진한 초록일수록 유효 페이지가 많음, 빨간 테두리 = 지금 쓰는 블록, 점선 = 빈 블록). 오른쪽은 WAF 추이와 OP에 따른 이론 곡선(점선)이다. OP를 5 %로 줄이면 WAF가 5를 넘고, 순차 쓰기에서는 블록이 통째로 무효가 되어 WAF가 1에 가깝다. 희생 블록 정책을 FIFO로 바꿔 차이도 비교해 보자. 실제 SSD는 여기에 더해 뜨거운 데이터와 차가운 데이터를 다른 블록에 모으는 분리 기법을 쓴다.

03웨어 레벨링

핫/콜드 부하에서 차가운 데이터가 든 블록은 거의 지워지지 않고, 뜨거운 블록만 계속 지워진다. 블록 하나라도 수명이 다하면 문제가 되므로, FTL은 지우기 횟수를 고르게 맞춘다. 빈 블록을 고를 때 덜 닳은 블록을 우선하는 동적 웨어 레벨링과, 오래 안 움직인 차가운 데이터를 일부러 많이 닳은 블록으로 옮겨 덜 닳은 블록을 순환에 끌어들이는 정적 웨어 레벨링이 있다. 정적 레벨링은 추가 복사를 만드니 WAF와 균등함 사이의 거래다.

읽는 법. 칸 하나가 블록, 색이 지우기 횟수(진할수록 많이 닳음)다. 레벨링이 꺼져 있으면 차가운 데이터 블록(옅은 칸)은 거의 새것인 채 남고 일부 블록만 닳는다. 켜면 색이 고르게 퍼져 수명은 늘지만, WAF도 함께 오른다. 옮겨진 차가운 데이터가 뜨거운 블록에 섞여 GC 때마다 다시 복사되기 때문이다. 그래서 실제 FTL은 옮긴 차가운 데이터를 따로 모아 두는 블록(콜드 스트림)을 둔다.

TRIM: "그 칸은 이제 안 써요"
파일을 지워도 운영체제는 보통 파일 시스템의 표만 고친다. SSD는 그 LBA가 쓸모없어졌다는 것을 모르고, GC 때마다 이미 지워진 파일의 페이지를 성실히 옮겨 쓴다. TRIM(NVMe에서는 Deallocate) 명령은 호스트가 "이 LBA들은 더 이상 유효하지 않다"고 알려 주는 방법이다. 해당 페이지는 즉시 무효가 되어 GC 복사가 줄고, 사실상 OP가 늘어난 효과를 낸다.

問확인 문제

호스트가 같은 LBA를 다시 쓰면 FTL은?

  1. 그 페이지를 지우고 같은 자리에 쓴다
  2. 빈 페이지에 새로 쓰고 매핑을 바꾼 뒤 옛 페이지를 무효로 표시한다
  3. 블록 전체를 즉시 지운다
  4. 쓰기를 거부한다

out-of-place update.

OP = 7 %일 때 균일 무작위 부하의 근사 WAF는?

  1. 약 1.1
  2. 약 2
  3. 약 7.6
  4. 약 0.5

(1 + 0.07)/(2 × 0.07) ≈ 7.6.

순차 쓰기에서 WAF가 1에 가까운 이유는?

  1. 블록 하나의 페이지들이 함께 무효가 되어 GC 때 복사할 유효 페이지가 거의 없어서
  2. 순차 쓰기는 NAND에 쓰지 않아서
  3. ECC가 꺼져서
  4. OP가 0이 되어서

한꺼번에 쓴 데이터가 한꺼번에 무효가 된다.

정적 웨어 레벨링의 대가는?

  1. 용량 감소
  2. 읽기 지연 증가
  3. ECC 약화
  4. 차가운 데이터를 옮기는 추가 쓰기 (WAF 약간 증가)

균등한 마모를 얻는 대신 복사가 늘어난다.
