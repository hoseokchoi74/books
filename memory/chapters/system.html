메모리 시스템과 계층 설계

어떤 메모리도 빠르고 크고 싸지 않다. 그래서 컴퓨터는 성격이 다른 메모리를 층층이 쌓고, 자주 쓰는 데이터를 위로 올린다. 데이터센터에서는 이 계층이 HBM, DDR, CXL 메모리, SSD로 넓어졌다. 이 장은 계층을 "설계"하는 관점 — 어떤 데이터를 어디에 두고, 각 층을 얼마나 둘 것인가 — 을 다룬다.

  • 메모리 벽이 시간이 지나며 어떻게 커졌는지 성장률로 설명할 수 있다.
  • 접근 빈도의 쏠림(Zipf 분포)이 계층 구조를 효과적으로 만드는 이유를 안다.
  • CXL 메모리 티어링과 핫/콜드 페이지 배치의 효과를 계산한다.
  • 용량·대역폭·비용 목표를 동시에 만족하는 메모리 구성을 설계한다.

01메모리 벽은 계속 높아진다

프로세서의 연산 능력은 코어 수와 벡터·행렬 유닛 덕분에 2년에 몇 배씩 늘었다. DRAM 대역폭은 같은 기간 1.5–2배, 지연은 거의 그대로다. 그 결과 연산 장치를 쉬지 않게 하려면 바이트 하나당 해야 하는 연산(필요 연산 강도)이 해마다 커진다. AI 가속기에서는 이 비율이 수백 FLOP/B에 이르러, 대부분의 작업이 메모리에 묶인다.

2000년 대비 연산
2000년 대비 대역폭
필요 연산 강도 (2000년 = 4)

읽는 법. 두 직선(로그 눈금) 사이의 간격이 메모리 벽의 높이다. 기본값은 대략적인 추세(연산 2년 2배, 대역폭 2년 1.45배)로, 2026년 값이 오늘날 AI 가속기의 수백 FLOP/B와 비슷해진다. 간격을 줄이는 방법은 세 가지다: 대역폭을 키우거나(HBM), 데이터를 재사용하거나(캐시·타일링), 데이터를 옮기지 않거나(11장 인메모리 컴퓨팅).

02뜨거운 데이터는 소수다

대부분의 작업에서 접근은 소수의 데이터에 몰린다. 페이지를 접근 횟수 순으로 늘어놓으면 k번째 페이지의 빈도가 \(1/k^s\)에 비례하는 Zipf 분포가 흔히 나타난다. s가 클수록 쏠림이 심하다. 그래서 빠르지만 작은 층에 상위 몇 %만 올려도 접근 대부분이 그 층에서 끝난다. 반대로 쏠림이 약하면 계층의 효과가 줄어든다.

최근 서버는 CPU에 직접 붙은 DDR 외에 CXL로 연결한 메모리 확장 장치를 둔다. 용량당 값은 비슷하거나 싸지만 지연이 DDR보다 수십~백여 ns 길다. 운영체제는 페이지 접근을 추적해 뜨거운 페이지는 DDR로, 차가운 페이지는 CXL로 옮긴다(티어링).

實驗실험 10-2DDR + CXL + SSD 티어링
DDR / CXL / SSD 접근 비율
평균 지연
전부 DDR 대비

읽는 법. 왼쪽은 페이지 순위에 따른 누적 접근 비율(어디까지 DDR·CXL에 담기는지 색으로 표시), 오른쪽은 층별 접근 비율이다. 지연은 DDR 90 ns, CXL 250 ns, SSD 80 µs로 가정했다. 쏠림이 강하면 DDR 20 %만으로도 거의 DDR 속도가 나온다. SSD까지 내려가는 접근이 0.1 %만 생겨도 평균이 크게 무너지는 것도 확인하자.

03용량·대역폭·비용의 삼각형

AI 서버를 설계한다고 하자. 모델과 데이터를 담을 용량, 연산 장치를 먹일 대역폭, 그리고 비용. HBM은 대역폭이 압도적이지만 비싸고 용량이 적다. DDR은 균형형, CXL 메모리는 용량을 싸게 늘리지만 대역폭이 작다. 아래 실험에서 목표를 맞추는 가장 싼 조합을 찾아보자.
